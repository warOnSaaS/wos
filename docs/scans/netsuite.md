## Scope

NetSuite ERP core and main modules: financials, OneWorld, order-to-cash, procure-to-pay, inventory/WMS, manufacturing, CRM, PSA (SuiteProjects and SuiteProjects Pro), SuiteCommerce, SuitePeople HR/payroll, planning (NSPB), SuiteCloud platform, SuiteAnalytics, plus the NetSuite mobile apps.

Left out of this scan:

- Industry editions and partner SuiteApps, not scanned module by module
- NetSuite Analytics Warehouse and NSPB internals, noted only
- Oracle Fusion Cloud ERP and other Oracle clouds, separate products

## Public API

**Style:** SOAP and REST web services (SuiteTalk), RESTlets (custom REST endpoints in SuiteScript), SuiteQL, SuiteAnalytics Connect; MCP server (AI Connector Service)

OAuth 2.0 is recommended for new REST integrations; token-based auth for SOAP. Concurrency limits are shared across SOAP, REST and RESTlets, and a REST governanceLimits operation reports them. REST batch operations can run in sequence.

## Getting data out

How a customer gets their data out of this product, from public sources: facts for a future shared import engine, not a design.

| Full extraction | Incremental (delta) | By API |
|---|---|---|
| partial | yes | yes |

Oracle states the Full CSV Export 'does not currently export all data' and points to a combination of saved searches, reports, SOAP web services and SuiteAnalytics Connect (a paid add-on) for complete extraction; REST record/SuiteQL/document services make extraction API-based. Incremental sync is documented for SOAP (search by lastModifiedDate plus getDeleted, anchored on getServerTime), and REST collection filtering supports date/time operators, but SOAP is being removed (gone with 2028.2).

### Auth for a third-party importer

**Models:** oauth-app, service-account, admin-consent, other

An administrator (or user with the Integration Application permission) creates an integration record (Setup > Integration > Manage Integrations > New) enabling Authorization Code Grant and/or Client Credentials (machine-to-machine); users then authorize the app, per account (authorizations are not copied to sandbox or Release Preview and must be redone after sandbox refresh). OAuth 2.0 applies only to REST web services and RESTlets; SOAP uses token-based authentication (TBA). SuiteAnalytics Connect uses driver credentials with certificate-based server auth plus Account ID and Role ID. Public clients cannot use client credentials. No marketplace review step was seen on the pages read.

### Rate limits and quotas

Concurrency is governed per account across all web services (SOAP, REST) and RESTlet requests combined. Base concurrent-request limit by service tier: legacy Shared/3 = 5, 2 = 10, 1/1+ = 15, 0 = 20; tiers for contracts from June 2020: Standard 5, Premium 15, Enterprise 20, Ultimate 20; +10 per SuiteCloud Plus license. Development and partner accounts are fixed at 5. TBA and RESTlets have no per-user limits (login/password SOAP keeps per-user limits). REST collections: 1000 results per page, max 1000 pages; 100,000 results max without Connect (one million with Connect); SuiteQL max 100,000 results. SOAP: search pageSize 5-1000 sync / up to 2000 async, getList 1000, asyncGetList 2000, request size 100MB. REST document service: 10 MB upload/download per request (413 above that).
