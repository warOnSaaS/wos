## 1. Summary (self-contained)

warOnSaaS's coordinator, wOS, leases small build units to contributors whose own Claude/ChatGPT subscriptions run the agents; two other contributors' agents (Astra on Codex, Fable on Claude) and a human review the work; the wOS GitHub App merges it. Amendment 02 adds an economy: **WOS**, a Solana token (devnet in V1), allocated by **Proof of Contribution**.

The design:
- **Receipts.** A merged unit produces an immutable ContributionReceipt. Execution work is weighted by the agent's provider usage, normalised to **ACU** by a versioned oracle (1 ACU = USD 1 of list-price API inference, never shown as money), **clipped at the unit's cap** (peer P75 × 1.25). Usage is **ATTESTED at best** (client-reported); run logs with exact per-turn totals are required; mainnet eligibility of attested usage fails closed until the founder decides. Planning, proposals, bugs, security and human review carry outcome weights (ACU-equivalents).
- **Epochs (weekly).** Budget = 3,327 ppm of the remaining 995M-WOS reserve (≈ 4-year half-life), split 60/10/5/5/15/5 (execution, planning, human review, outcomes, completion accrual, security reserve). Distributing slices emit at most a **rate ceiling** (100 WOS/ACU, decaying) × weight; the rest returns to the reserve; accruals scale with utilisation. One conserved equation: reserve + pools + security reserve + issued = 995M.
- **Optimistic payouts.** CALCULATING (48 h: sampled audits 5%, canaries, bounded holds) → PROPOSED (every allocation public with an explanation and deterministic anomaly metrics; 48 h challenge window; silence accepts) → FINALIZED (per-beneficiary entitlements: 50% released now, 50% held back 13 epochs). Any epoch participant can dispute any set of allocations in one frozen bundle (per-item stake, floor 1 WOS, forfeited per rejected item); the dispute focuses a sealed payout-audit gate of 2 random outside-feature auditors on their own subscriptions; outcomes UPHELD/CLIPPED/REVOKED; one appeal; bounty 20% of what was RECOVERED. Proven cheating is confiscated from protocol-held amounts only (holdback, pending, unclaimed, unreleased Genesis vesting), with notice, reply and appeal; then offsets, revocation, exclusion. Released tokens are never seized.
- **Bootstrap.** The founder may merge anything (public label) but his own work gets PROVISIONAL receipts that count only in devnet test epochs until independently ratified. Genesis credit for pre-protocol work is valued by accepted output only (retro size points × reference ACU × early rate), capped at 0.5% of supply, issued only at mainnet with 2-year vesting, approved by ≥ 2 non-founder humans.
- **Solana.** Token-2022 with metadata only; no freeze, no permanent delegate, no transfer hook. Devnet: claim-triggered push transfers — signed transaction persisted before broadcast, one active attempt per leaf, replacement only after a historical search, confirmation at finalized commitment, adapter generations fenced; epoch roots anchored by SPL Memo; no custom programs. Mainnet: an audited escrow releasing a few epochs at a time, mint revoked; migration drains in-flight transfers, then snapshots.
- **Governance.** Policy numbers are data, forward-only, previewed by the simulation. Founder mode until an activation threshold; then tiered supermajorities (60/70/75%, emergency > 50%) in BOTH locked-token (≥ 12 months) and 6-month contribution weight, denominators over distributed supply only, 10% cap per organization.
- **Organizations** can be beneficiaries; org-mates are related accounts for every independence rule.

Artifacts: 18 design documents, draft contracts that typecheck with 52 tests, draft migration 0007 (rewritten as v2) applied in `db:test` with 124 rejection assertions (plus positive checks) including Astra-02's repros A–G, and a deterministic simulation whose tables are regenerated by the test suite.

## 4. Questions for review 03 (ranked by what worries the architect most)

1. **Verify section 3b item by item.** For each Astra-02 finding, is it resolved in the code and migration as claimed? Re-run repros A–G mentally against the new 0007 (and read the matching db assertions): is each now rejected for the RIGHT reason, and is there a variant that still passes?
2. **Engine v2 conservation.** Find any path (returns, corrections, confiscations, disputes, write-offs, holdback maturation, offsets, pool payouts, loss absorption, person/org splits) that breaks R + ΣP + S + I = reserve, lets a balance go negative, double-counts, or lets rounding be steered.
3. **Holdback and confiscation.** Can a cheater escape confiscation (claim fast, rebind wallets, move to an organization beneficiary, split across beneficiaries)? Can confiscation be abused against an honest contributor despite notice, reply, appeal and two-person actions?
4. **Fabrication economics (A2).** Are the model and its sensitivity axis honest? What detection rate is realistic, and is F1 framed correctly?
5. **Settlement v2.** Is persisted-signed-transaction + one active attempt + historical resolution + finalized confirmation actually exactly-once on Solana, including RPC gaps and migration?
6. **Disputes v2.** Frozen bundles, per-item stakes, priority for unrelated disputers, derived settlements, one appeal: what remains gameable (extortion, retaliation, friendly disputers, appeal abuse)?
7. **Relatedness and independence.** Beyond G-80, what defeats the live related-account function and the per-round/per-quorum locks?
8. **Governance caps.** Is water-filling with a feasibility guard correct and sufficient? Beneficial-owner aggregation relies on declared controllers — what breaks it?
9. **Anything new** introduced by this fix pass that is wrong, unsafe or unimplementable.
