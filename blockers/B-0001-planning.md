## Interim readings implemented (please ratify or correct)

Everything below is implemented in `packages/planning/src/build-graph.ts` and pinned by tests. None of it changes a frozen file.

1. **ABU_REPO_UNKNOWN.** Registry = the two repositories the contracts name (`PLATFORM_REPO` platform, `PRODUCT_REPO` product; exported as `REPOSITORY_FAMILIES`, mirroring migration 0005's seed rows). An ABU in any other repository is unknown; an ABU whose family differs from the first registered ABU's family is flagged. Without the contract's repository the validator cannot tell WHICH family is right, only that the graph mixes them; the database trigger remains the final check.
2. **REQUIREMENT_SURFACE_NOT_IN_SCOPE.** A requirement tagged with surface S is flagged when `wos.json` `apps` is non-empty and has no app shell for S, or when no profile that lists the requirement has an acceptance suite for S (a profile's acceptance surfaces are used as that app's in-scope surfaces). A requirement in no profile is not judged.
3. **JOURNEY_UNCOVERED.** Any of: a surface used by some requirement has no journey; a journey links no requirement tagged with its own surface; a journey links a requirement no ABU implements (unless already reported REQUIREMENT_UNCOVERED); no profile has an acceptance suite on the journey's surface that includes one of the journey's requirements (policy rule "a journey no acceptance suite exercises").
4. **NATIVE_CAPABILITY_UNPLANNED.** Only journeys on `ios`/`android` with non-empty `nativeCapabilities` (a web journey with `offline_storage` needs no native module). The graph must contain an ABU that implements one of the journey's requirements AND whose write scope can touch a `wos.json` `toolchainRequirements[].paths` glob (that is the contracts' definition of native paths).
5. **TOOLCHAIN_WITHOUT_RESOURCE at graph time.** An exact write scope that matches a `toolchainPaths` glob needs `toolchain:<scope>` exclusive; a tree scope needs `toolchain:<p>` for every LITERAL toolchain path p inside it. A tree scope that could merely contain a wildcard match (`modules/x/**` vs `**/package.json`) is not flagged, or every ABU would need a toolchain claim; the changeset validator still checks each concrete file at submission.
6. **WRITE_OUTSIDE_MODULE_OR_PRODUCT.** Allowed roots: `modules/<feature>/`, `features/<feature>/acceptance/`, and the app-shell paths from `wos.json` `apps` (falling back to `apps/web`, `apps/mobile` when `apps` is empty). A TGT-00 (platform family) graph writing `packages/**` would fail this rule; TGT-00 contracts are not validated this way in V1, but the rule needs a platform-family reading before they are.
7. **KEY_NOT_IN_FEATURE** is also used (with `abu: null`) when `BUILD-GRAPH.yaml` `feature` differs from `CONTRACT.yaml` `feature`. `graph.contractVersion` vs `contract.version` has no code and is NOT checked.
8. **Glob matching.** `@waronsaas/planning` has no `picomatch` dependency and the lockfile is frozen, so it carries a small segment matcher (`*`, `?`, `**`, `{a,b}`, case-insensitive, dot files matched) for `toolchainPaths` and `toolchainRequirements`. Request: add `picomatch` to planning's dependencies in the next dependency batch so both packages share one glob engine.
